## What this session was for

Fix the standards-admin page becoming fully unclickable after deleting a standard (REQ-033), and fix the aspect header card staying stale after renaming an aspect while the sidebar list updated (REQ-038).

## What changed

**REQ-033 (`3c587b6`):**
- `DeleteConfirmationModal.tsx` — `onConfirm` may return a Promise; confirm handler awaits it, shows loading state, and only closes on success; dismiss blocked while confirming.
- `SortableStandardCard.tsx` — delete menu item uses `onSelect` + `preventDefault` + `setTimeout(0)` so the Dialog opens after the DropdownMenu fully closes.
- `StandardsManagement.tsx` — aspect delete from the settings dropdown uses the same deferred `onSelect` pattern.

**REQ-038 (`49ac78b`):**
- `StandardsManagement.tsx` — derive `currentAspect` from the live `aspects` array by `mat_aspect_id` instead of reading a stale `selectedAspect` snapshot; removed the post-save `setTimeout` that re-applied an old `aspects` closure ~100ms after rename.

## Root cause

**REQ-033:** Opening a Radix `Dialog` directly from a `DropdownMenuItem` `onClick` while the menu is still tearing down leaves `pointer-events: none` on `body`. The delete modal also called `onOpenChange(false)` synchronously alongside an async delete, which could race overlay cleanup.

**REQ-038:** After rename, `updateAspect` refreshed `aspects` in the hook, but the header read `selectedAspect` — a snapshot set at selection time. A `setTimeout` tried to re-sync from `aspects`, but closed over the pre-rename array and overwrote fresh data.

## Assumptions made

- Deferring dialog open by one tick after dropdown close is sufficient for all delete entry points (standard card menu and aspect settings menu).
- Deriving `currentAspect` from `aspects` by id is enough; `selectedAspect` remains the selection handle and existing `useEffect` sync still covers delete/selection edge cases.

## Findings — flagged, not fixed

1. **REQ-007 vs REQ-033 — not the same cause.** REQ-007 is Popover-in-Sheet on the assessment invitation date field; REQ-033 is DropdownMenu-to-Dialog on standards admin. Both are Radix overlay stacking, but different components and flows.

2. **`use-assessments.ts`** still fabricates group-level `last_updated` when standards lack timestamps (REQ-011 class).
