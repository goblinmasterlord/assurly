## What this session was for

Implement the two Ratings-page filter defects that share a school-vs-aspect collapse in `SchoolPerformanceView`: aspect filter (REQ-008) and status filter (REQ-009). Separate atomic commits so either can be reverted alone.

## What changed

**REQ-008 (`8390ecd`):**
- `SchoolPerformanceView.tsx` — when aspect filters are active, narrow `assessmentsByCategory` before render; drop schools with no matching aspects. Category option values and `categoryValueToAspect` keys now use shared `aspectCodeToCategory` from `data-transformers.ts`.
- `Assessments.tsx` — same `aspectCodeToCategory` for dept-head aspect options; localStorage restore validates against those values (was comparing to raw aspect codes like `edu`, which silently cleared restored filters).

**REQ-009 (`9a6bda1`):**
- `SchoolPerformanceView.tsx` — status filter uses the same aspect-row narrowing pattern; overdue uses `isOverdue({ status, due_date: cat.dueDate ?? null })` instead of `status === "not_started"`.

**Schema changes:** none.

**Contract changes:** none.

## What was deliberately not changed

- Backend / API contract (explicitly out of scope).
- School header metrics from `GET /api/dashboard/schools` (still school-level aggregates when the dashboard overlay is present).
- Dept-head `Assessments.tsx` status filter (already row-per-aspect and already used `isOverdue`).
- `calculateSchoolStatus` / unfiltered school badge when no status filter is active.
- Due-date persistence (REQ-007); production has no due dates, so overdue will not appear in live data until that lands.

## Root cause

Both filters kept a school if **any** aspect matched, then rendered **all** `assessmentsByCategory` rows. Aspect and status are aspect-level dimensions, so the fix is to filter the nested aspect list and only then decide school visibility.

REQ-008 additionally had duplicated legacy category maps; localStorage restore validated the wrong vocabulary.

REQ-009’s overdue branch treated every `not_started` aspect as overdue.

## Assumptions made

- Combining aspect + status filters is AND on the aspect row (filter category, then status on the remainder) — matches “every other filter works in combination” intent.
- `cat.dueDate` on school performance rows is the correct field for `isOverdue` (populated from assessment `due_date` when present).

## Findings — flagged, not fixed

- None new beyond known REQ-007 dependency: overdue cannot be UAT’d against production data until due dates exist.
