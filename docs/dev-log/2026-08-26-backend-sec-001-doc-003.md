## Root cause

Both requirements trace to the same failure mode, which is worth naming once: **a document
was updated to describe an intention rather than an observation.** The v1.8 pass wrote
"REQ-003 shipped some time ago" without checking, and every downstream document inherited it
— the data model, the changelog, and the dashboard's `evidence_count` field, which has been
counting rows in an unwritable table ever since. SEC-001 is the mirror image: the *code* was
right and the *documents* were silent, so an auditor reading only documents reached a false
conclusion in the opposite direction.

## Findings — flagged, not fixed

- **`GET /api/dashboard/schools` returns `evidence_count`, which is structurally always `0`**
  for every school in every MAT and has been since it shipped. Now documented in both the
  contract and the data model. It is not a dashboard bug — there is nothing to count — but
  any analytics work treating it as signal is reading a constant.
- **Known Issue #12 still holds and is understated.**
  `GET /api/standards/{mat_standard_id}` omits `standard_type` from the response dict — and
  **also from the versions array**, despite the versions query selecting it (`main.py:1235`).
  The issue as written mentions only the first. Natural companion to REQ-011.
- **`DELETE` on standards, aspects and action items requires authentication only** — any user
  in the MAT may call them. Correct per the Internal tier of the role model, but it means
  **read-only access cannot currently be granted to anyone**, because the External tier does
  not exist. That is REQ-013, and it is a bigger gap than "trustees can't log in yet".
- **`SUPER_ADMIN_EMAILS` is read once at import** (`auth_config.py:50`), so changing the
  allow-list requires a redeploy, not a restart or a config reload. Correct and arguably
  desirable, but worth knowing before someone tries to revoke access in a hurry.
- **Four routes have no dependencies at all**: `request-magic-link` and `verify/{token}`
  (public by design), `/api/terms` (Known Issue #9), `cleanup-expired-tokens` (Known Issue
  #8). That is the complete list — verified by enumerating every route's dependency list, not
  by sampling.

  sampled, to answer SEC-001's "confirm the check is present and correct on **every**

  dashboard `view` param, `school_type`, `is_central_office`, `evidence_count` and
  `outstanding_actions_count` fields; all four action endpoints; `standard_type` on the
  by-aspect and single-assessment responses. Verdicts are in the v2.7 changelog row.
