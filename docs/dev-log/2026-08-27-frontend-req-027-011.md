## What this session was for

Ship the create-path cache invalidation that was manufacturing duplicate assessments (REQ-027), then stop the standards-admin UI fabricating “updated today” when `updated_at` is absent (REQ-011 frontend half).

## What changed

**REQ-027 (`43a92f7`):**
- `AssessmentInvitationSheet.tsx` — create now goes through `assessmentService.createAssessments` (enhanced service) instead of the raw `assessment-service` export, which never touched the cache.
- `enhanced-assessment-service.ts` — on successful create, invalidate both `assessments` and `terms` caches. Existing `onSuccess={refreshAssessments}` then refetches and updates the list; the Ratings term selector is derived from assessments, so a newly used term appears there without a full reload.

**REQ-011 (`b701b31`):**
- `SortableStandardCard.tsx` — removed `|| new Date()`; absent `updated_at` renders `Updated —`.

**Schema changes:** none.

**Contract changes:** none.

## What was deliberately not changed

- Backend / contract (out of scope for both).
- Expanded-school aspect-metrics invalidation (REQ-027: report only).
- `use-assessments.ts` group-level `last_updated` / `lastUpdated` fabrication via `new Date().toISOString()` (REQ-011: report only).
- `VersionHistoryModal.tsx` same `|| new Date()` pattern (named in the plan; not in this brief’s file list).
- Binding standard cards to a real timestamp (blocked on backend exposing `updated_at` on `GET /api/standards`).

## Root cause

**REQ-027:** The invitation sheet called the uncached create helper. `refreshAssessments` still ran after the toast, but `getAssessments()` hit a still-valid `requestCache` entry and returned the pre-create list. Terms on the Ratings page come from that same list, so they stayed stale too. Enhanced `createAssessments` already invalidated `assessments` but was unused by the sheet, and never invalidated `terms`.

**REQ-011:** Contract list standards omit `updated_at`; the card treated missing as “now”.

## Assumptions made

- Invalidating `assessments` + refetch via existing `onSuccess` is sufficient for the Ratings term selector (it builds `availableTerms` from the assessments prop, not from `GET /api/terms`).
- Live create UAT against a running stack was not available in this session; verification is by call-path and typecheck (see Verification).

## Findings — flagged, not fixed

1. **Expanded-school aspect metrics vs REQ-027 — related cache surface, different defect.** Rating saves already call `invalidateByPrefix('aspect_')` and `SchoolPerformanceView` listens via `subscribePrefixInvalidation` to drop `aspectRowMetrics` / loaded-key refs. Create previously skipped the enhanced path entirely, so those listeners never ran. After REQ-027, create still does **not** invalidate `aspect_` or `dashboard_schools` (out of scope). The deferred expanded-school edge case is about incomplete UI/ref bookkeeping when `aspect_` *does* invalidate; REQ-027 was about never invalidating the list caches. **Not the same cause — do not widen REQ-027.**

2. **`use-assessments.ts` (`transformAssessmentByAspectToAssessment`)** still invents group-level timestamps: `last_updated: lastUpdatedFromStandards || new Date().toISOString()` and the same for `lastUpdated`. Same fabrication class as REQ-011; left untouched per brief.

3. **`VersionHistoryModal.tsx:77`** still has `standard.updated_at || standard.created_at || new Date().toISOString()` (plan note).
